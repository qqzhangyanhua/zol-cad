# 16 — 本厂数据导出与删除

**What to build:** **管理员**能把本厂的全部数据一次性导出，也能彻底删除——合作终止时数据可以带走或清除。

这不是可有可无的合规装饰。机加工厂的客户**零件图**普遍涉密、常带 NDA，而 ADR-0005 决定把图纸上传到第三方云。工厂能不能拿回和清掉自己的数据，是采购谈判里会被直接问到的问题；答不上来，成交就卡在安全问卷环节，跟识别准确率没有关系。

**Blocked by:** 04

**Status:** claimed

- [x] **管理员**能导出本厂全部数据，含**零件图**原文件、提取结果、**复核**结果、**风险标签**、**报价任务**、**修正记录**
- [x] 导出格式可被人和程序读取，不是黑盒
- [x] **管理员**能发起删除本厂全部数据，需要二次确认
- [x] 删除同时清除对象存储中的原图文件，不留孤儿文件
- [x] 删除后再登录看不到任何残留数据
- [x] 导出与删除都严格限定在本厂租户边界内
- [x] 缝 1 有测试证明：删除 A 厂数据后 B 厂数据完好无损

## Comments

实现已落在 PR：https://github.com/qqzhangyanhua/zol-cad/pull/16

设计要点：

- 管理员专用。`GET /admin/tenant-data/export`、`POST /admin/tenant-data/delete-challenge`、`POST /admin/tenant-data/delete`。报价员 403。租户只来自 Actor，请求里的 `factory_id` 无效。
- 导出是 ZIP：`README.md`、`manifest.json`、零件图 / 报价任务 / 修正记录的 JSON+CSV、`originals/<id>/<原文件名>`。JSON 是完整数据（提取字段、复核状态、现算的风险标签）；CSV 同一份表格视图。不是专有黑盒。
- 二次确认是服务端一次性令牌 + 短语 `删除{工厂名}的全部数据`。只弹浏览器 alert 过不了。错短语 / 错令牌 / 过期 / 已用都 400，数据不动。令牌约 10 分钟有效，新发起会作废旧的未用令牌。
- 删除清掉本厂零件图、事件、修正记录、报价任务、人工基线、本厂偏好、确认挑战，并按已记录的 storage key 删对象存储原图。工厂、账号、会话、报价底稿 onboarding 模板留下，所以还能登录，只是业务列表是空的。
- 未做票 17。

- 缝 1：`120 passed`（真实 Postgres + Alembic `0011_tenant_data_export_delete`）。含导出包内容、报价员 403、错短语不删、确认后甲厂列表/统计/处理记录为空且原图 FileNotFound、乙厂零件图与原图仍在。
- 前端 `tsc --noEmit` 与 eslint 通过。
- 对运行中的后端/BFF 走了一遍：`quoter_a` 上传后导出 403；`admin_a` 导出 ZIP 含原图与风险标签；错短语 400 且数据还在；正确令牌+短语后列表空，再登录仍空，账号还在。`/admin/tenant-data` 管理员页有导出/删除、无字段映射文案；报价员打开该 URL 被 307 到零件图。
