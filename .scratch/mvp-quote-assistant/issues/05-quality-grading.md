# 05 — 图纸质量分级与差图劝退

**What to build:** **报价员**上传**零件图**后，立刻看到这张图的**图纸质量分级**（清晰 / 一般 / 差）。分级为"差"时系统直接劝退、建议走人工，而不是硬给一份看起来很自信的错结果；报价员若确信这张图可读，可以显式选择"仍然继续"，但这份结果从此永久带着"低质量图，结果不可靠"的标记。

这一票引入**提取引擎 Port**（输入是图像/PDF 页与零件族标识，输出是结构化提取结果与质量分级信号）以及 fixture 驱动的假实现。生产实现留到票 17。

**这一票还背了一条基础设施要求**：**零件图**状态机每次迁移都要写一条带时间戳的事件。ADR-0006 说得很直白——每次处理必须留关键时间戳，不能事后补。票 11 的**处理耗时**完全靠它，而事后给已有数据补时间戳是补不出来的，所以状态机诞生的这一刻就得带上。

**Blocked by:** 04

**Status:** ready-for-agent

- [ ] 上传后**零件图**自动进入分级，完成后展示清晰 / 一般 / 差三档之一
- [ ] 分级为"差"时不自动预填，界面劝退并建议走人工
- [ ] 差图上有明确的"仍然继续"入口，选择后可继续处理
- [ ] 显式继续产生的结果永久携带低质量标记，在详情页与列表都可见
- [ ] 界面明确说明**图纸质量分级**只表示图纸本身的质量、不代表结果可以免核
- [ ] 上传装配图或爆炸图时被明确告知不在处理范围
- [ ] 提取引擎 Port 落地，用例层只依赖该抽象；假实现由 fixture 驱动，按输入图标识返回预置结果
- [ ] **零件图**状态机落地：已上传 → 分级中 → 已分级，差图分支进入"建议人工"，可被显式覆盖回主干
- [ ] 每次状态迁移写一条带时间戳的事件，事件可按**零件图**查询
- [ ] 缝 1 有测试证明：分级为"差"的图不自动预填、显式覆盖后结果带低质量标记
