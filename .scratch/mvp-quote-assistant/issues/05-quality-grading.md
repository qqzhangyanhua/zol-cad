# 05 — 图纸质量分级与差图劝退

**What to build:** **报价员**上传**零件图**后，立刻看到这张图的**图纸质量分级**（清晰 / 一般 / 差）。分级为"差"时系统直接劝退、建议走人工，而不是硬给一份看起来很自信的错结果；报价员若确信这张图可读，可以显式选择"仍然继续"，但这份结果从此永久带着"低质量图，结果不可靠"的标记。

这一票引入**提取引擎 Port**（输入是图像/PDF 页与零件族标识，输出是结构化提取结果与质量分级信号）以及 fixture 驱动的假实现。生产实现留到票 17。

**这一票还背了一条基础设施要求**：**零件图**状态机每次迁移都要写一条带时间戳的事件。ADR-0006 说得很直白——每次处理必须留关键时间戳，不能事后补。票 11 的**处理耗时**完全靠它，而事后给已有数据补时间戳是补不出来的，所以状态机诞生的这一刻就得带上。

## Comments

实现已落在 PR：https://github.com/qqzhangyanhua/zol-cad/pull/5

设计要点：

- 上传成功后同步走分级：已上传 → 分级中 → 已分级（清晰/一般）或建议人工（差）或不在范围（装配/爆炸图）。
- `ExtractionEngine` Port 输入为图像/PDF 页 + 零件族标识 + 输入图标识；输出为结构化提取 + 图纸质量分级。用例层不引用假引擎。`FixtureExtractionEngine` 按文件名中的 fixture id（`FX-TQ-01` / `FX-TA-01` / `FX-TP-01` / `FX-ASM-01` 等）返回预置结果。
- 差图 `auto_prefill_allowed=false`；显式「仍然继续」回到已分级并永久写下 `low_quality_unreliable`。装配图不可走仍然继续。
- 每次状态迁移写 `part_drawing_events`（含时间戳与序号），`GET /part-drawings/{id}/events` 可按零件图查询。
- 租户隔离：甲厂读乙厂事件或仍然继续均为 404。
- 缝 1：35 passed。前端 tsc + lint 通过。浏览器已走通清晰/差/仍然继续/装配图不在范围。
