# 17 — 接入真实提取引擎与保密说明

**What to build:** 把 fixture 驱动的假引擎换成票 02 选定供应商的真实实现，让**读图取数**真正跑在多模态大模型上。同时给**管理员**一页保密说明，写清图纸存在哪、由谁处理、是否会被用于训练——让他能回答自己客户的保密质询。

真实实现只需满足票 05 定下的同一个 Port，用例层与领域层不应有任何改动；如果发现要改，说明 Port 设计漏了东西，先修 Port。

**供应商契约测试单独打标记，不进默认 CI。** 它会真实调用大模型、要花钱、结果不稳定，作为默认测试集的一部分会让 CI 变得又慢又不可信。它的用途是换供应商或供应商升级模型时，手动跑一遍验证输出契约没变。

保密说明页不是营销文案，是采购环节的实用工具。ADR-0005 的判断是：只要工厂或其客户担心"图纸出厂、被用于训练、泄密担责"，采购就可能在安全问卷环节谈崩，与识别准确率无关。所以把三条硬门槛的落实情况明明白白写出来，把保密从技术问题转成合同问题正面回应。

**Blocked by:** 02, 06

**Status:** ready-for-agent

- [ ] 选定供应商的真实提取引擎实现落地，满足既有 Port，用例层与领域层无改动
- [ ] 真实引擎的返回结果同样经过适配器边界的严格校验，校验不通过按提取失败处理
- [ ] 调用失败、超时、限流有明确的失败状态与可重试路径
- [ ] 调用日志不落图像内容
- [ ] 单张调用成本可观测，便于验证期核算
- [ ] 供应商契约测试单独打标记，默认 CI 不执行，可手动运行
- [ ] 切回假引擎的开关保留，缝 1 的集成测试不受影响
- [ ] **管理员**能看到一页保密说明：图纸存储位置与区域、处理方所属供应商、不用于训练的书面承诺、DPA 签署情况
- [ ] 保密说明内容与票 02 的 ADR 结论一致，不出现无依据的承诺
