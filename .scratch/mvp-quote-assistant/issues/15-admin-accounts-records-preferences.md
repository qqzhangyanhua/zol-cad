# 15 — 管理员：账号、全厂记录、偏好配置

**What to build:** **管理员**能为本厂的**报价员**创建账号、查看全厂的处理记录、配置本厂的常用材料与**风险标签**优先级，并查看当前生效的风险规则清单及其阈值——知道系统在按什么标准提醒他的团队。

权限只有**管理员 / 报价员**两档，不做细粒度权限。**报价员**默认只看到自己处理的**零件图**与**报价任务**；**管理员**能看到全厂的。

**这里没有导出字段模板配置。** 模板由团队在 onboarding 手工配好（见票 14）。如果将来有人想把它加进这个页面，先回头读 ADR 与 spec 里的取舍理由。

角色权限解决的是"内部越权访问"这一层；"图纸出厂上第三方云"那一层的顾虑由供应商合同门槛解决（ADR-0005），两者互补，谁也替代不了谁。

**Blocked by:** 03, 07

**Status:** claimed

- [x] **管理员**能创建、停用本厂的**报价员**账号
- [x] **报价员**默认只看到自己处理的**零件图**与**报价任务**
- [x] **管理员**能查看全厂所有处理记录
- [x] **管理员**能配置本厂常用材料列表，该列表在**复核**时作为材料字段的候选
- [x] **管理员**能调整**风险标签**的展示优先级，界面按该优先级排序
- [x] **管理员**能查看当前生效的风险规则清单及阈值（只读）
- [x] **管理员**界面中不存在**报价底稿**字段映射配置入口
- [x] 任何角色都读不到其他工厂的数据

## Comments

实现已落在 PR：https://github.com/qqzhangyanhua/zol-cad/pull/15

设计要点：

- 范围过滤在用例层：`TenantScope` 仍只管工厂；`actor_can_see_owned` / `filter_owned_by_actor` 再按角色收窄。报价员只看见自己上传的零件图、自己创建的报价任务；管理员看全厂。列表、详情、复核、归入/移出、导出都走同一套，不信任客户端。
- 账号：管理员只能创建/停用本厂报价员。`users.disabled_at`；停用后登录 401「账号已停用」，并吊销该用户会话。不能停用管理员，也不能跨厂。
- 全厂处理记录：`GET /admin/processing-records` 只给管理员，带上传人用户名。
- 本厂偏好：`factory_preferences` 存常用材料与风险标签展示顺序。任何本厂角色可读（复核材料候选）；只有管理员可写。`to_part_drawing_response` 与复核页 `RiskLabelList` 都按该顺序排序。规则是否触发仍由领域纯函数决定，不改阈值。
- 风险规则清单只读：`GET /admin/risk-rules` 暴露 `list_risk_rule_definitions()` 的规则标识、标签、暂定阈值。阈值仍是 ADR-0007 示例 / 接线占位，不是票 01 结论。
- **没有**报价底稿字段映射 UI / HTTP 写入。模板仍是票 14 的 onboarding 后台配置。分层测试继续禁止前端出现「字段映射 / 导出模板 / source_key」。

验证：

- 缝 1：`116 passed`（真实 Postgres + Alembic `0010_admin_accounts_preferences`）。含同厂报价员互不可见、管理员可见、跨厂隔离、创建/停用、材料与优先级、只读规则、映射入口 404。
- 前端 `tsc --noEmit` 与 eslint 通过。
- 通过 Next.js BFF/SSR 走了一遍：`admin_a` 创建 `quoter_e`、配材料 `45#`/`40Cr`、优先级「细长优先」、只读规则含阈值；`quoter_a` 上传后 `quoter_e` 列表为空且详情 404；`admin_a` 的零件图列表与处理记录看得到；停用后登录 401「账号已停用」；`admin_b` 看不到华东精密账号与图纸。本环境无可用的交互式浏览器，Chrome headless 截图未产出；页面 HTML 已确认管理员页有账号/材料/规则、无字段映射文案。
- 未做票 16 / 17。未加导出模板映射入口。
