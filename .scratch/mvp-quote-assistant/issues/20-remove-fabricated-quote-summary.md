# 20 — 撤掉伪造的报价摘要卡片与无功能按钮

**What to build:** 删掉 `CadDrawingReviewSummary` 里所有系统根本不产出的内容，以及 `AppHeader` 上三个没有行为的按钮。这不是设计品味问题，是产品承诺被界面推翻了。

设计重构（`572e79b`）在**零件图**详情页最上方加了一张摘要卡，位置在真实**复核**工作台之前，是**报价员**打开一张图第一眼看到的东西。它的内容几乎全是写死的常量：

- **定价**：`batchPrices` 四档写死单价（¥2450.8 / 2012.6 / 1856.4 / 1528.7），成本拆分按 `currentPrice / 1856.4` 的比例缩放出材料费、加工费、表面处理费、检测包装费。
- **工时**：「交付周期（估算）12 - 15 工作日」。
- **工艺**：四条写死建议（「建议增加内圆角 R1.5」「3x M6 螺纹孔建议改为通孔」等）。
- **不存在的字段**：净重 2.348 kg、毛重 2.812 kg、总体积 318.7 cm³、「图纸版本 V2.1」、「与历史同类项目相比加工成本高出约 12%」、历史项目「3D-VALVE-017 / ¥1,782.0」。

定价、工时估算、工艺路线三项是 spec `Out of Scope` 里逐条点名排除的（ADR-0001「我们替你抄写，不替你判断」）。对外的价值主张是"少抄写、看得更快"，界面却先给了一个报价数字——这直接把产品定位换掉了。

有两处比越界更严重：

1. **风险标签为空时编造风险。** 卡片在 `risk_labels` 为空的分支里渲染四个虚构风险（薄壁「多处壁厚 < 2.0mm」、深孔「ф6.0 深径比 > 6」、公差累积、材料去除率「局部 > 85%」）。这些数不来自任何提取值。
2. **前端自算风险评分并输出「低风险」。** `riskScore = riskCount === 0 ? 3.5 : 5.5 + riskCount * 0.85`，再按阈值映射成「高风险 / 中等风险 / 低风险」。无标签时得到 3.5 分、显示「低风险」。

ADR-0007 与用户故事 24、25 反复强调的那条不变量是：**永远不说"没风险"，沉默不能被读成安全**——因为一个错误的"无风险"直接作用于定价决策，会让报价员不上浮报价而亏本干活。后端严格守住了这条（空态由后端下发固定文案「未发现可判定的风险项，不代表此件无风险」，词表里不存在任何"安全/通过"语义的标签）。这张卡片把它整个盖掉了，而且盖法比输出"无风险"更糟：它在真正无标签时既编造了四个不存在的风险、又在同一屏给出「低风险」评分。

顺带两处小的：

- 材料字段为空时回填 `"AL6061-T6"`，材料下方固定副标题写「铝合金」（无论实际材料是 45# 还是 40Cr）。用户故事 18 要求图上没有的字段如实留空，「空值本身就是一个可信的信号」。
- 详情页在**零件图**未归入任何**报价任务**时（这是合法状态）把项目代码回填成写死的「新项目-240518-A」。

`AppHeader` 的「保存草稿」「导出报告」「提交报价」三个按钮全都没有 `onClick`。它们只在 `actions` prop 未传时渲染，而全仓库没有任何一处传 `actions=`，所以这三个按钮出现在**所有页面**上。「提交报价」尤其有害：**报价任务**是纯归集层，没有金额、没有审批流、任务自身没有状态机，这个按钮向用户承诺了一个不存在且被 spec 明确排除的动作。

**处理方式**：摘要卡不必整个删掉，但只允许展示后端真实下发的值——图号、零件名称、材料、状态、真实**风险标签**、**图纸质量分级**。任何"值为空就给个合理默认"的兜底分支一律去掉，空就显示空。评分、定价、交期、工艺建议整块移除。两个死的 CTA（`onScrollToForm` 从未被传入）要么接上要么删掉。
