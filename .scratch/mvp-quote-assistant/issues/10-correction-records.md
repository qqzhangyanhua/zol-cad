# 10 — 修正记录

**What to build:** 系统为**报价员**每一次对提取值的修改留下一条不可变的**修正记录**（原值 → 新值、字段类型、操作人、时间、所属**零件图**）。**管理员**能看到全厂的修正统计，知道哪类字段最常被改——也就是 AI 在哪儿还不靠谱。

**用途要如实、不夸大**：MVP 阶段这些数据用来积累修正样本以备将来自建或微调、并驱动提示词与后处理规则的迭代。**不是实时优化模型**——提取引擎是通用闭源大模型，用户修正根本无法回流去再训练它（ADR-0003）。界面上不要出现任何暗示"越用越准"的措辞。

**Blocked by:** 08

**Status:** claimed

- [x] **修正记录**不可变，不随后续修改被覆盖；同一字段多次修改产生多条记录

## Comments

实现已落在 PR：https://github.com/qqzhangyanhua/zol-cad/pull/10

设计要点：

- 修正记录是追加写、不可变。`UpdateExtractedField` 与 `AddCriticalDimension` 在事务里按修改前后的值 diff 出记录；确认 / 忽略不写。同一字段多次修改产生多条。补录原值为空，补录额外槽（`kind__added__N`）按规范字段类型归并。
- 字段类型用规范槽位的中文名（最严公差、图号…），管理员统计按该类型聚合频次。
- 最小管理员：种子账号 `admin_a` / `admin_b`。`GET /correction-stats` 仅管理员；`GET /part-drawings/{id}/correction-records` 按工厂租户过滤。报价员打开统计页会被挡回零件图列表。
- 用途文案由领域常量 `CORRECTION_STATS_PURPOSE` 下发，写明积累样本、迭代提示词与后处理；提取引擎是闭源大模型，修正不回流再训练。不出现「越用越准」「自动学习」。
- 不做票 11（处理耗时）和票 15（账号管理 / 全厂处理记录 / 材料与风险优先级配置）。

验证：

- 缝 1：82 passed。含「修正后能读到原值与新值都正确的记录」、多次修改不覆盖、补录原值为空、管理员按类型看频次、甲厂报价员/管理员读不到乙厂记录、文案不含实时优化措辞。
- 前端 `tsc --noEmit` 与 eslint 通过。
- 浏览器：报价员改最严公差 / 最大外形、补录最深孔后记录落库；报价员无「修正记录」入口且打统计 URL 被挡回；`admin_a` 看到按字段类型的频次与诚实用途说明；`admin_b` 看到「本厂还没有修正记录」。
