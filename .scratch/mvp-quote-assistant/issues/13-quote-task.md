# 13 — 报价任务归集

**What to build:** **报价员**创建一个**报价任务**、填上名称与客户，把多张**零件图**归入其中，对应真实的"一次询价含多个零件"；归错了能移出或移到别的任务。历史记录页能按客户、时间、状态找回过去的任务。

**报价任务**是**轻量归集层**，不是订单实体：它只负责把多张图的结果归到一起并支撑汇总导出（票 14），**不含金额、不含审批流、不含状态流转**。产品的核心仍是单张图的提取与复核。这条边界要守住——一旦开始往里加金额和审批，它就变成了一个订单系统，而定价判断明确不在范围内（ADR-0001）。

单张**零件图**可以不属于任何**报价任务**而独立存在。

## Comments

实现已落在 PR：https://github.com/qqzhangyanhua/zol-cad/pull/13

设计要点：

- 报价任务只做归集，不是订单。表 `quote_tasks` 只有 `id / factory_id / name / customer_name / created_at / created_by_user_id`。没有金额列，没有审批列，任务自身没有状态机。
- 零件图用可空外键 `part_drawings.quote_task_id`：一张图同时最多属于一个任务；`NULL` 表示未归集，上传后默认就是这样。改归是改这条外键，不是多对多。
- 历史页的「状态」是读时推导，不落库：无成员图 → `无零件图`；有图且至少一张不是「已复核」→ `复核未完成`；有图且全部「已复核」→ `已复核`。这是检索维度，不是任务审批流。
- 租户与零件图一致：工厂级 `TenantScope`，`execute()` 不接受 `factory_id`。报价员看见本厂全部任务（不是按创建人过滤；全厂管理员视角是票 15）。
- HTTP：`POST /quote-tasks`、`GET /quote-tasks`（客户名 / 创建时间 / 推导状态）、`GET /quote-tasks/{id}`、`POST .../part-drawings`（归入或改归）、`DELETE .../part-drawings/{drawing_id}`（移出）。零件图响应多了 `quote_task_id`。
- 未做票 14（汇总导出）及之后。没有加金额、审批、任务状态流转。

验证：缝 1 本地 `104 passed`（含 `test_quote_tasks.py`：创建、归入、移出、改归、未归集、一对一、按客户/时间/状态检索、详情带各图复核状态、响应无 amount/price/approval；`test_tenant_isolation.py`：乙厂报价员看不到甲厂任务）。GitHub CI seam-1 backend + frontend 已绿。前端 `tsc --noEmit` 与 eslint 通过。浏览器走通：报价员创建任务 → 上传图后可归入 → 可改归到另一任务或移出成未归集 → 历史页按客户与推导状态找回 → 任务详情列出各图复核状态 → 乙厂账号看不到甲厂任务。
