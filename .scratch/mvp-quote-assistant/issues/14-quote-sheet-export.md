# 14 — 报价底稿导出

**What to build:** **报价员**在**报价任务**上点一次导出，拿到一份每个零件一行的**报价底稿**（xlsx / csv），直接用于内部核算或对外报价。这份表长得就像这家工厂现在用的那份，不需要再手工搬一次列。

**字段模板不做自助配置 UI。** 每家工厂的映射模板在 onboarding 时由团队按其现有底稿手工配好，作为一份后台配置存在，不出现在**管理员**界面里。这是"服务代替功能"的刻意取舍：字段映射 UI 要引入一整套映射概念（源字段、目标列、缺省值、顺序），成本高，而每家工厂一辈子只用一次。

导出内容里**必须带上风险标签**——否则报价员在界面上看到的加工难点会在最后一步悄悄丢失，而定价恰恰发生在这张表上。非**目标零件族**的实验性标记同理，下游看表的人需要知道哪几行更不可靠。

## Comments

- 2026-08-25: 落地报价底稿导出。PR：https://github.com/qqzhangyanhua/zol-cad/pull/14

  设计：
  - 用例 `ExportQuoteSheet`：租户从 Actor 来，不接受 `factory_id`。行组装在领域层 `quote_sheet.py`。xlsx/csv 字节在适配器 `OpenpyxlQuoteSheetFileWriter`。
  - 列模板按工厂存 `quote_sheet_templates`（JSONB）。没有 HTTP 写入入口，管理员页也没有字段映射。onboarding 插一行即可；没有行时用默认底稿（标题栏 + 关键尺寸 + 技术要求 + 三列必带标记）。模板漏配风险标签 / 实验性 / 低质量图时，领域层补在末尾，避免定价用表丢掉界面上已看见的难点。
  - 风险标签按当前确认值现算，空单元格就是空，不写「无风险」。非目标族写「实验性、不保证」。票 05 显式继续留下的 `low_quality_unreliable` 写成「低质量图，结果不可靠」。
  - 任务里任何一张不是「已复核」就 409，文案点名文件名：`报价任务中还有未完成复核的零件图：…`。详情页按钮也会先列出还差哪几张。
  - HTTP：`GET /quote-tasks/{id}/quote-sheet?format=xlsx|csv`。未做票 15+。

  验证：
  - 缝 1 本地 `111 passed`（含 `test_quote_sheet_export.py`：行数=零件数且含风险标签列与实验性列、csv 同样、未复核点名拦截、工厂自定义列顺序、低质量图标记进表、没有模板 CRUD 路由；租户隔离：甲厂导出乙厂任务 404）。前端 `tsc --noEmit` 与 eslint 通过。
