# 26 — 提取进度要能区分阶段，让人分得清"在跑"和"卡住"

**What to build:** 用户故事 10 的动机写得很直白：「我想在提取进行中看到进度状态，**以便我知道是在跑还是卡住了**」。现在的实现恰好无法回答这个问题。

`PartDrawingWorkspace` 对「已上传」「分级中」「提取中」三个状态渲染**同一个面板**，只传 `drawingId` 不传 `status`。面板内容是一句静态文案：

> 正在处理零件图
> 系统正在做图纸质量分级并读图取数。请稍候，完成后会在左侧预填表单。

没有 spinner、没有进度条、没有已等待时长、不区分现在到底在分级还是在取数。配上每秒静默 `router.refresh()`，视觉上和"卡住"完全一样——正是这条 story 想解决的问题。

这在假引擎下无所谓（瞬时返回，面板一闪而过）。真实多模态大模型单张十几秒起步，一次批量传 10 张就是几分钟；而且票 19 的机制里，进程重启会把滞留在「分级中」「提取中」的图回收为**提取失败**，意味着"长时间无反馈然后突然失败"是一个真实会发生的场景。此时**报价员**没有任何信号判断该继续等还是该去点重试。

**要做的**：把 `status` 传进面板，三个阶段各自有对应文案（等待处理 / 正在评估图纸质量 / 正在读图取数），加上一个明确的进行中视觉信号和已等待时长。等待超过某个阈值时给出"仍在处理中，可稍后回来查看"这类兜底提示——不要谎称快好了，也不要让人以为界面死了。

**不要做的**：不要为了显示百分比而编一个假进度条。系统不知道模型什么时候返回，编造的进度条属于同一类"界面比系统更自信"的错误（参见票 20）。阶段名 + 已等待时长是诚实且够用的。

顺带：批量上传时列表页也应该能一眼看出哪几张还在跑、哪几张已好、哪几张失败了。列表目前对进行中状态每秒 refresh，但视觉区分度不够。

**Status:** claimed

- [x] 进行中面板接收 `status`，「已上传」「分级中」「提取中」三态文案各不相同
- [x] 有明确的进行中视觉信号（不是纯静态文本）
- [x] 显示已等待时长
- [x] 超过合理阈值后给出兜底提示，且不谎称进度
- [x] 不出现编造的百分比进度条
- [x] 列表页能一眼区分进行中 / 已提取 / 提取失败
- [x] 轮询在图纸进入终态后停止，不无限空转
