# 11 — 处理耗时与人工基线对比

**What to build:** **管理员**录入几条纯人工作业的计时作为基线，然后看到本厂的**处理耗时**与基线的对比，从而用客观数据判断这工具到底省没省时间。

这是 ADR-0006 在产品里的落点。MVP 的目的是验证价值，若无内建测量手段，三个月后只会得到"感觉还行"这种无法证伪的主观印象。省时必须用客观数据证明，不能靠问卷。

**处理耗时**由票 05 埋下的状态迁移事件算出：从"上传"到"已复核"两个时间戳之差，各阶段时长可分解。人工基线由管理员在试用初期手工计时几张纯人工作业后录入。

## Comments

实现已落在 PR：https://github.com/qqzhangyanhua/zol-cad/pull/11

设计要点：

- 处理耗时是读时计算，不落额外计时列。领域函数 `processing_time_from_events` 取该图第一条「上传」与第一条「已复核」事件的时间戳之差；缺任一时间戳则整张图排除。
- 阶段分解：分级 = 上传 → 已分级，提取 = 已分级 → 已提取，复核 = 已提取 → 已复核。差图劝退后覆盖回到主干时，分级包含劝退等待。
- 人工基线单独表 `manual_baselines`（零件描述 + 秒），由管理员录入。对照页给出本厂平均处理耗时、基线平均、节省秒数，以及逐图 / 逐条明细。
- 只有管理员能打 `GET /processing-time` 与 `POST /manual-baselines`；报价员 403。租户仍走 `TenantScope`，请求里的工厂标识被忽略。
- 演示账号补上 `admin_a` / `admin_b`（与同厂报价员共用演示密码）。
- 缝 1：76 passed。前端 tsc + lint 通过。浏览器已走通：管理员录入 20 分钟基线 → 报价员看不到对照页 → 走完一张清晰图复核后对照显示节省 → 乙厂管理员看不到甲厂数据。
