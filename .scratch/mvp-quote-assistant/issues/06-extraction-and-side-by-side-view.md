# 06 — 读图取数与并排展示提取结果

**What to build:** **报价员**打开一张已分级的**零件图**，看到左边是预填好的提取结果表单、右边是原图的并排界面。表单里已经填好**标题栏**字段（图号、零件名称、材料、数量）、**关键尺寸**与公差、以及技术要求（热处理、表面处理、粗糙度等），按字段类别分组展示。

这一票只做展示，逐项确认与修改留到票 08。

有两条产品承诺必须在这里兑现。一是**图上没有的字段如实留空**，不编造一个看起来合理的值——空值本身就是一个可信信号，编造出来的值则会直接毁掉信任。二是"本工具不替代看图，请重点复核公差密集区与技术要求"的提示常驻可见（ADR-0004）：纯大模型提取会**漏提**，而漏提无法被"需确认"标记——你不能对一个不存在的字段打标记，所以 MVP 对漏提的唯一防御就是并排原图加这句提示加人自查。

**Blocked by:** 05

**Status:** claimed

- [x] 分级完成后自动触发**读图取数**，界面显示提取进行中的状态
- [x] 提取完成后展示左表单右原图的并排界面，原图区可缩放平移
- [x] 提取出**标题栏**字段：图号、零件名称、材料、数量
- [x] 提取出驱动成本的**关键尺寸**与公差（最严公差、最大外形、最深孔、最薄壁等）

- [x] 每一项都标明所属字段类别（**标题栏**字段 / **关键尺寸** / 技术要求），可按类别快速扫过
- [x] 图上没有的字段如实留空，不填编造值

## Comments

实现已落在 PR：https://github.com/qqzhangyanhua/zol-cad/pull/6

设计要点：

- 分级进入主干（已分级）后，同一请求里自动走 `ExtractPartDrawing`：已分级 → 提取中 → 已提取。差图仍停在建议人工；显式仍然继续回到已分级后再自动提取。装配/爆炸图不提取。
- 复用票 05 的 `ExtractionEngine` Port 与 fixture 假引擎。fixture 改为原始 dict，经适配器 `parse_engine_result`（Pydantic `extra=forbid` + 字段目录对齐）才变成领域对象。校验失败抛 `ExtractionValidationFailed`，状态进提取失败，脏字段不落库。
- 表单槽位固定：标题栏（图号 / 零件名称 / 材料 / 数量）、关键尺寸（最严公差 / 最大外形 / 最深孔 / 最薄壁）、技术要求（热处理 / 表面处理 / 粗糙度）。引擎没返回的槽位保持 `null`。未知文件名走 DEFAULT，全部留空。
- ADR-0004 文案由后端写入 `look_at_drawing_disclaimer`，详情页黄条常驻，没有关闭按钮。
- `POST /part-drawings/{id}/extract` 用于提取失败后的一键重试，读已存原图，不要求重新上传。
- 未做票 08 的逐项确认/修改，未做风险标签 / 复核完成 / 导出 / 真引擎。
