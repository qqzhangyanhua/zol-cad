# 提取引擎选用通用多模态大模型（买，而非自建）

MVP 的目标是在 3 个月内验证"能否缩短报价时间 + 工厂是否愿付费"，而不是自研 CV 能力。因此提取引擎直接采用通用多模态大模型（图片/PDF 页交给模型返回结构化结果），而非自建 OCR + 视觉管线，也不做混合方案。

**接受的代价**：
- 每张图有 API 调用成本（需在成本控制上做限额，见上传页数/大小限制）。
- 模型会产生幻觉（编造图上不存在的尺寸/公差）——由信任模型（ADR-0002：整图分级 + 高风险字段强制复核）兜底。
- **无法用用户修正去再训练闭源模型**。

**数据飞轮如实降级**：MVP 阶段的"修正记录"定位为——(1) 积累修正数据，为将来自建或微调做准备；(2) 驱动提示词与后处理规则的迭代。**不是**实时优化模型。不给自己和用户画短期兑现不了的饼。

**供应商硬门槛**（见 ADR-0005）：因客户图纸涉密，供应商选择不能只看识别效果，必须同时满足：**数据存储在境内、书面承诺不用于模型训练、可签数据处理协议（DPA）**。不满足者一票否决。

**演进路径**：待价值验证、调用量上升、成本敏感后，再把高频稳定部分（如标题栏）下沉到自建/混合方案。
